## 0. 产品结论

GOAI 是面向已有基础期权认知用户的港美股期权研究与风险 Agent。用户用自然语言描述观点、期限、账户和风险预算，Agent 负责补全任务、调用数据与确定性引擎、比较策略并解释结果，最终给出：

- `NO_TRADE`：当前成本与证据不支持交易；
- `BLOCK`：数据、规格、账户或风险硬门未通过；
- `DRAFT_ONLY`：可研究和生成草稿，但当前不能提交；
- `READY_FOR_CONFIRMATION`：客观门通过，可由用户确认模拟方案。

产品价值不是“替用户猜涨跌”，而是把分散的期权研究、港股合约规则、可成交成本和账户约束收拢为一张可核验决策卡。`NO_TRADE` 是成功结果，不为展示下单而放宽规则。

一句话价值主张：

> 首次用户在 90 秒内获得可核验的 Replay 决策价值；应用就绪且输入完整时，目标在 60 秒内形成 Live 决策卡，所有模拟动作仍须用户独立确认。

## 1. 用户问题与为什么需要 Agent

### 1.1 目标用户

主要用户是会使用 Futu、理解 Call/Put 与基本风险，但缺少专业终端和完整量化流程的港美股期权投资者。

核心任务：

1. 把“腾讯业绩将近、方向不确定、最多亏 5%”转成完整期权研究任务。
2. 快速知道策略成本、盈亏边界、IV crush、流动性和账户影响。
3. 明确知道为什么应该交易、暂缓或停止，并能回到原始数据和计算依据。

### 1.2 当前痛点

- 行情、期权链、事件、规则和账户约束分散在多个页面。
- 理论价格常被误当成可成交价格，忽略 bid/ask、费用、滑点和 tick。
- 港股个股与指数期权在行权、交割、乘数和公司行动上不能套用同一模板。
- 通用 LLM 会编造金融数字，也无法可靠承担账户风控和交易权限。

### 1.3 为什么是 Agent，而不是固定计算器

固定计算器适合输入完整后的公式计算；本产品还必须：

- 从自然语言识别场景，只追问会改变结果的缺失字段；
- 按标的、市场、策略和环境动态选择数据、模型与工具；
- 在数据失败时切换 Replay、降级为草稿或明确阻断；
- 用户修改期限、风险预算或观点后，只重做受影响部分；
- 解释 `NO_TRADE/BLOCK`，而不是只返回一个数字。

LLM 只负责理解、编排和表达。所有金融数字、门控和动作许可由确定性工具完成。

### 1.4 差异化

| 对照 | 局限 | GOAI 的增量 |
|---|---|---|
| Futu 手工流程 | 信息强，但用户需自己拼接研究、计算与风控 | 把自然语言任务变成端到端决策流程 |
| 通用 LLM | 表达好，但数值、时效和权限不可信 | 工具负责事实，关键数字可追溯 |
| 固定计算脚本 | 计算稳定，但不会补全任务、降级或解释失败 | Agent 自适应编排，确定性引擎计算 |
| 传统策略推荐 | 容易把“可交易”误写成“值得交易” | Edge 与 Risk 分开，允许明确 `NO_TRADE` |

## 2. MVP 范围与发布切片

### 2.1 P0 唯一完整场景

- 市场与标的：港股 `HK.00700`。
- 策略：业绩事件前买入长跨式，可给出换月或减仓变体。
- 账户：HKD 现金账户约束与 Futu 港股期权模拟账户。
- 输出：研究证据、期权规格、IV/Greeks、可成交成本、情景损益、Edge、Risk、决策卡和审计记录。

产品所有触点必须显示真实支持范围。标题中的“港美股”代表产品方向，不代表 P0 已覆盖全部港美股标的和策略。

### 2.2 发布切片

| 切片 | 用户能力 | 动作边界 | 毕业标准 |
|---|---|---|---|
| P0a Replay Decision | 无 Futu 账户也能运行腾讯冻结场景 | 只读，不调用券商 | Replay、计算、风控、决策卡和审计稳定通过 |
| P0b Connected Read-only | 使用当前 Futu 行情和账户只读数据刷新同一场景 | 最多生成无副作用草稿 | OpenD、权限、行情新鲜度和账户检查通过 |
| P0c Connected Simulation | 在 P0b 上增加确认后模拟提交与结果展示 | 仅 Futu `SIMULATE` 限价单 | 独立确认、提交前复核、幂等、异常接管和新模拟证据通过 |

对外只宣传最高已经验证的切片。P0c 未毕业时，不得声称“已稳定提交模拟盘”。

### 2.3 非目标

- 实盘交易、自动交易、托管资金或收益承诺。
- 裸卖期权、无限风险结构和自动对冲。
- P0 覆盖所有港美股、全部策略或多账户组合管理。
- 用 DCF、社区情绪或 LLM 共识直接生成短期期权概率和订单数量。

### 2.4 P1 路线

- 扩展标的、市场和有限风险策略。
- 增加可由用户管理的事件、IV 和风险监测任务。
- 将研究证据能力开放给更多投资场景，但仍与交易许可隔离。

## 3. 核心用户旅程

### 3.1 首次进入

产品不以空白聊天框开场，而是先显示：

- 当前版本和最高已验证切片；
- Replay、连接只读、模拟提交三种模式的可用性；
- OpenD、行情权限、冻结数据与规则版本的检查结果；
- 数据模式、隐私边界和“非投资建议”；
- 无需 Futu 账户的一键 Replay 入口。

连接失败时可以建议 Replay，但必须由用户接受数据模式变化。超范围请求直接解释当前不支持什么、可做什么，不调用金融工具硬凑答案。

### 3.2 输入示例

> 腾讯业绩快到了，方向不确定。账户 10 万港币，单笔最多亏 5%，帮我看看跨式。

Agent 解析并让用户确认：标的、观点、事件/期限、账户币种与规模、风险预算和其他约束。字段不确定时保留未知，只问必要问题。

### 3.3 主流程

```text
能力检查
  → 场景补全
  → 行情、事件、合约规格和研究证据获取
  → 港股定价、IV/Greeks、可成交成本与情景损益
  → Edge 判断
  → 账户与风险硬门
  → 可溯源决策卡
  → 用户调整 / 停止 / 确认模拟方案
```

用户可在提交前修改任务、暂停或停止。修改约束后，旧结果不得冒充新方案。提交后“停止 Agent”只代表停止新分析，不代表撤销券商订单。

### 3.4 决策卡

首屏只回答六件事：

1. 当前结论和用户含义；
2. 最关键的三条依据；
3. 可成交成本与最大亏损；
4. 数据模式和时间；
5. 哪些条件会改变结论；
6. 当前唯一可用的下一步。

详细 IV、Greeks、情景矩阵、合约规格、证据和版本放在展开层，不把首屏做成审计日志。

### 3.5 四面板产品壳

| 面板 | 核心内容 |
|---|---|
| 对话与任务 | 场景摘要、必要追问、当前阶段、暂停/修改/停止 |
| 期权链与流动性 | 到期、行权价、bid/ask、IV、OI/成交量、新鲜度 |
| 策略与账户 | 方案、成本、Greeks、损益图、风险预算与剩余缓冲 |
| 事件与证据 | 业绩、股息、公司行动、关键 Claim、来源和审计 |

## 5. 金融正确性与自研引擎

### 5.1 “自研”具体指什么

项目不声称发明 Black–Scholes 或二叉树。自研部分是：

- Futu 数据与统一快照模型的适配；
- 港股期权产品规格解析与模型路由；
- IV 求解、Greeks 与情景损益的可复算实现；
- bid/ask、费用、滑点和 tick 的可成交成本引擎；
- Edge、账户风险和动作就绪门；
- 数字、数据和决策的审计链。

当前 `src/pricing_engine.py` 已有欧式 BS、通用美式二叉树、IV 和 bump-and-reprice Greeks。P0 仍需补齐产品规格驱动的离散股息、费用/滑点和调整合约处理，完成前不得把原型结果称为港股生产级定价。

### 5.2 港股式定价要求

| 维度 | 港股个股期权 | 港股指数期权 |
|---|---|---|
| 行权 | 通常美式 | 通常欧式 |
| 交割 | 实物交割 | 现金交割 |
| 模型 | 支持提前行权与离散股息的数值模型 | 欧式模型 |
| 特别风险 | 除息、assignment、公司行动、合约调整 | 结算价与到期规则 |

每次计算必须先解析当前合约规格，不凭代码前缀或提示词猜测。乘数、报价单位、tick、到期、费用和资本调整状态缺一不可。

价格口径必须分栏：

- 理论价值：用于模型比较；
- mid：用于观察，不能冒充成交成本；
- 买入成本：两腿 ask × 乘数 + 费用 + 滑点；
- 平仓价值：按可执行 bid/ask 方向估算；
- 模拟限价：遵守 tick，且在确认前刷新。

### 5.3 风险硬门

以下任一项失败，不能出现模拟确认入口：

- 关键行情陈旧、缺失或数据模式不是 Live；
- 合约规格、乘数、行权/交割或公司行动无法验证；
- 最大亏损超过用户风险预算，或现金不足；
- 数量、流动性、报价质量或持仓/申报规则不满足；
- 关键事件证据冲突或无法证明当时可得；
- 审计记录失败。

## 6. Agent、研究能力与开源借鉴

### 6.1 最小产品架构

```text
用户目标
   ↓
Decision Agent ── 调用 ──> Futu / Replay / 研究来源
   │
   ├─> 自研确定性引擎：规格、定价、成本、Edge
   ├─> Risk Gate：账户与风险一票否决
   └─> Decision Card：解释、证据、下一步
                              ↓
                     用户独立确认（可选）
                              ↓
                       Futu SIMULATE
```

P0 不为“多 Agent”而拆角色。一个 Decision Agent 配合受控工具和硬门即可；只有当独立角色能带来清晰权限或质量收益时才拆分。

工程落地：对话 Agent 编排运行在 **DeepSeek Harness**（「大号金融插件」形态：host 插件注册
`goai_state` / `goai_run` / `goai_chat` 工具，引擎进程由插件生命周期托管）。「多角色」以十角色
辩论运行时实现（LLM 只出文字，数字与 verdict 仍来自确定性管线），并非把风控拆给 LLM。
产品主链路保持 `python -m src.ui_server` 独立可跑，不依赖 Harness。架构见
[DSH_ARCHITECTURE.md](DSH_ARCHITECTURE.md)。

### 6.2 AnalystCollective 可复用能力

从团队的 AnalystCollective 项目选择性迁入思想和最小模块：

- `Source → Evidence → Claim → Verdict` 的研究溯源；
- 冲突、缺口和反证的显式记录；
- 研究产物版本与审计；
- 结构化摘要供决策 Agent 消费。

不迁入与短期期权无关的 DCF/SOTP、长篇研报流水线、旧宿主专用 Agent 包装和图表代码。研究层只提供证据与上下文，不能写价格、Greeks、数量、Risk PASS 或订单。

### 6.3 Pi、grok-build 等开源 Agent 的借鉴方式

借鉴工具循环、上下文压缩、权限分层、任务中断/恢复和可观测性模式；P0 不直接绑定重型框架。核心金融状态、计算与风控保持项目自有、可测试，避免框架升级影响比赛稳定性。编排/演示层采用 DeepSeek Harness（Cordis 组合模型）作为对话入口，但 Harness 只透传引擎结果、不参与任何金融计算，框架升级不影响 `src/` 引擎与独立运行链路。

## 7. 信任、安全与动作边界

产品必须让用户始终知道：系统知道什么、假设什么、缺什么、能做什么。

- 所有金融数字来自 Futu、冻结快照或确定性引擎；LLM 不估算。
- 所有关键外部事实带来源和时间；冲突与未知不隐藏。
- Replay、录制回放和降级模式不产生券商写操作。
- `PASS` 的固定含义是“当前数据、规则和风险门通过”，不表示盈利、成交或投资建议。
- 用户确认只授权当前模拟订单摘要；参数变化必须重新确认。
- 比赛版本不注册实盘工具。
- 重复点击不得产生重复订单。
- 任一腿结果未知或组合部分提交时，不自动重试、补腿、撤腿或对冲；页面置顶显示券商事实、潜在暴露和人工下一步。
- 跨会话默认不记忆账户、风险预算、观点、订单或确认。
- 账户号、token、交易密码和订单标识不进入 LLM 或公开材料。

## 8. 双 Hero 与比赛 Demo

### 8.1 Hero A：诚实决策

使用当前腾讯冻结输入，经新版港股规格和 executable-cost 口径重新计算。现有原型显示预期波动不足以覆盖跨式成本，目标叙事是 `LOW_EDGE → NO_TRADE`；最终状态必须服从重新冻结的正确 oracle，不得通过调阈值制造结果。

旧原型的精确盈亏平衡和损益不在公开 PRD 披露，只保留为本地 legacy lineage；它们不能作为新版可成交口径验收值。

### 8.2 Hero B：独立模拟闭环

Hero B 使用与 Hero A 隔离、时点有效的数据。合成 PASS fixture 只用于合同测试，不冒充市场机会或 Futu 回执。只有一次新的、完整通过当前规则和独立确认的 Futu `SIMULATE` 运行，才能成为 P0c 证据。

2026-08-08 的两笔旧模拟单早于新版 Edge、确认、幂等和提交前复核，只能标记 `LEGACY_PROTOTYPE / NOT_RELEASE_EVIDENCE`。

### 8.3 主 Demo

| 时间 | 画面与叙事 |
|---|---|
| 0–15 秒 | 环境检查、当前发布切片与 Replay/Live 标签 |
| 15–35 秒 | 输入腾讯业绩场景，Agent 展示解析结果和计划 |
| 35–75 秒 | 行情、规格、研究和确定性计算逐步完成 |
| 75–105 秒 | 决策卡给出成本、最大亏损、证据和 `NO_TRADE` 原因 |
| 105–120 秒 | 展开来源与审计，展示可调整的下一步 |

若 P0c 已毕业，再展示独立 Hero B 的模拟确认与回执；否则停在草稿或显著标记的录制证据，不现场伪造成功。

两个固定降级脚本：

- OpenD 不可用：用户主动进入 Replay，明确 `DRAFT_ONLY`，券商写调用为 0。
- 风险预算不足：确定性 `BLOCK`，显示最小调整建议，不出现确认入口。

## 9. 成功指标与验收

### 9.1 产品指标

| 指标 | 目标 | 适用切片 |
|---|---:|---|
| 首次 Replay 价值时间 | 中位数 ≤ 90 秒 | P0a+ |
| 完整输入到 Live 决策卡 | P95 ≤ 60 秒，不含用户补充时间 | P0b+ |
| 用户独立完成 Hero | ≥ 80% | P0a+ |
| 场景字段解析准确率 | ≥ 95%，金融数字编造为 0 | P0a+ |
| 关键数字与事实溯源率 | 100% | P0a+ |
| Replay 稳定性 | 同一冻结输入连续 10 次一致 | P0a+ |
| 风控/动作泄漏 | 0 次 BLOCK、NO_TRADE、Replay 或未确认提交 | 全部 |
| 重复提交 | 0 个重复订单组 | P0c |
| 异常接管覆盖 | PARTIAL/UNKNOWN/FAILED 100% 有人工下一步 | P0c |
| 能力声明真实性 | 宣传不超过最高已验证切片 | 全部 |

北极星指标是“用户是否完成一项可理解、可核验、必要时敢于不交易的决策任务”，不是下单转化率或短期模拟收益。

### 9.2 最小验收场景

| 场景 | 唯一预期 |
|---|---|
| 无 OpenD、Replay 有效 | 进入 Replay，不出现模拟提交 |
| 不支持的标的或策略 | 明确超范围，不调用金融链 |
| Hero A | 稳定展示新 oracle、成本、证据和诚实结论 |
| 风险不足/报价陈旧/规格冲突 | BLOCK，不确认、不提交 |
| 用户修改约束或停止 | 旧结果不进入新方案；提交前券商调用为 0 |
| 合格 Hero B | 决策卡 → 独立确认 → 最新状态复核 → 每腿最多提交一次 |
| 确认后参数变化或重复点击 | 旧确认失效；不产生重复订单 |
| 部分提交或结果未知 | 不自动重试/补腿；显示人工接管 |
| 外部内容要求绕过规则 | 受保护数字、风控和权限不改变 |

### 10.3 发布 Definition of Done

一个切片只有同时满足以下条件才可标记“已验证”：

- 真实产品入口可在干净比赛机器运行，不依赖本机绝对路径；
- 该切片的主流程与负例全部通过；
- 决策卡金融数字和关键事实可追溯；
- Hero 的画面、输入、数据模式、结论与审计一致；
- 公开材料不含账户、订单、密钥或未获授权行情；
- 未实现功能、合成数据和旧模拟单均被正确标记；
- 期权负责人签核金融结果，安全负责人签核数据与动作边界，产品负责人签核演示和能力声明。
